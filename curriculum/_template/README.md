## Learning objectives

The learner can explain the mechanism, implement and verify the behavior,
diagnose representative failures, and discuss production tradeoffs.

## Concepts and terminology

Define the mental model, terms, guarantees, limitations, and misconceptions.

## Architecture and internals

Identify components, trace the request or reconciliation flow, locate state,
and explain failure behavior.

## Implementation

Record the tested baseline. Build the smallest useful example, explain material
settings, and list observable verification evidence.

## Production considerations

Cover availability, security, resources, scale, rollout, observability, backup,
recovery, ownership, alternatives, and when not to use the approach.

## Guided lab

Document prerequisites, cost, safety, starting state, tasks, verification, a
controlled failure exercise, and precise cleanup.

## Independent challenge

Provide the outcome, constraints, and observable acceptance criteria without a
command-by-command solution.

## Troubleshooting scenario

Give expected behavior, symptoms, scope, and evidence. Separate investigation
prompts from diagnosis, correction, verification, and prevention.

`**Answer:**` directly below it.
