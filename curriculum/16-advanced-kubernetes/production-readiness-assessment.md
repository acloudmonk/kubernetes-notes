# Final Production-Readiness Assessment

> **Module:** [16 — Advanced Kubernetes](README.md) · Previous: [Lab 3 — Design and rehearse fleet failover](labs/03-fleet-failover.md) · Next: [Independent challenge](independent-challenge.md)

This is the capstone assessment for [Gate 5](../ASSESSMENT-GATES.md#gate-5--production-readiness).
Score Explain, Build, and Diagnose with the repository rubric; each must reach 2
and the total must reach 7. Reassessment uses a changed failure scenario.

## Evidence packet

1. Reproduce infrastructure and delivery from reviewed versions without exposing credentials.
2. Trace source, tests, digest, SBOM, scan, signature/provenance, admission decision, GitOps revision, and runtime identity.
3. Demonstrate capacity and scaling evidence plus one safe disruption.
4. Rehearse an API/add-on/node upgrade and an application rollback or forward fix.
5. Restore application data in isolation and measure achieved RPO/RTO.
6. Run a timed incident, preserve a decision log, communicate impact, recover a business transaction, and write a blameless postmortem.
7. Defend architecture, tenancy, identity, network, storage, observability, capacity, cost, recovery, multi-cluster, and extension choices.

Every claim identifies evidence, owner, limitation, and cleanup. Do not submit
state, keys, kubeconfigs, tokens, production data, or unredacted diagnostics.
Passing means the learner can adapt the method, not merely replay scripts.

## Graduation output

Publish a concise architecture diagram, ADR index, operational readiness review,
risk register, runbook index, measured gate score, and a 30/60/90-day improvement
plan. Link existing module evidence instead of duplicating sensitive output.
